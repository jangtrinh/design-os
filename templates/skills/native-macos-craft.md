# Skill: Native macOS craft

Use this skill while the native macOS workflow is composing, reviewing, or repairing a routed native
surface. It turns the knowledge core into a bounded craft check; it does not authorize a stronger
delivery claim than the activation receipt.

## What to read

1. `knowledge/native-macos-craft.md` — SwiftUI ownership, finite proposals, scroll ownership,
   AppKit escalation, and evidence boundaries.
2. `knowledge/content-design.md` — content hierarchy and error copy when the native task includes
   labels, notices, empty states, or recovery paths.
3. `knowledge/design-review.md` — independent review and handoff when the work has a reviewable
   artifact.
4. `knowledge/verification-honesty.md` — evidence tiers and refusal semantics before reporting
   status.

## What to enforce

- Start in SwiftUI. Escalate to AppKit only for a documented ownership gap.
- Give flexible content a finite proposal and keep one scroll owner per interaction path.
- Test compact/error states as real navigation and focus paths, not a static screenshot.
- Keep deterministic, rendered, accessibility, reviewer, and owner evidence distinct.
- Preserve `PROVISIONAL` assurance and `QUALIFIED_DELIVERY_FORBIDDEN` in every delivery summary.
