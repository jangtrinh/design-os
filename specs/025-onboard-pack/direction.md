## What (one sentence)

When design:os onboards a design system from a codebase, the user-facing deliverable is a
**consumable skill pack** — an Agent-Skills-compatible folder that any fresh agent session can
invoke to design correctly with that brand — generated by the same split Claude Design proved:
**the host model authors sources; the kernel deterministically emits everything machine-facing.**

## Why

Spec 009 ends the code road at "components register" — registry rows. Rows are not a deliverable
a user can hand to an agent. The PCP experiment demonstrates the missing last mile and its exact
anatomy, and independently re-confirms four of our hard-won rules (border-box 1px, count-before-
target, hole-is-a-decision, respect-their-DS) — signal that the shape is invariant, not
PCP-specific.

## The architectural insight that changes the cost

Claude Design re-implemented 36 components as `.jsx` + a 190KB bundle **because its runtime is
walled** — it cannot execute the user's code. design:os lives inside the user's repo. The
components already exist, run, and are tested. **Therefore the pack points at their code instead
of copying it.** No React re-implementation, no bundle. (Owner fork: native format; a
Claude-Design-compat emitter is an explicit non-goal now, door left open as a future phase.)

## Pack anatomy (native)

```
.claude/skills/<brand>-design/       # or a path the user chooses; Agent Skills layout
  SKILL.md                           # kernel-emitted from verbatim template (PCP's, brand-substituted)
  readme.md                          # model-authored design bible — REQUIRED sections:
                                     #   Sources / CONTENT FUNDAMENTALS / VISUAL FOUNDATIONS /
                                     #   ICONOGRAPHY / Intentional additions / Not built / Caveats
  tokens.css or pointer              # POINTS at the repo's real token file(s); copies only when
                                     #   the source is generated-and-stable (see instrument)
  components/<Name>.prompt.md        # per-component usage law distilled from USAGE SITES,
                                     #   each carries the repo path of the real implementation
  guidelines/*.card.html             # specimen cards — reuse `ds specimen` machinery;
                                     #   many small cards (sub-concept granularity), @dsCard tag
  _adherence.<linter>.json           # KERNEL-EMITTED from registry/contracts — model never writes
  _pack_manifest.json                # KERNEL-EMITTED index (components, cards, tokens, hashes)
```

Model-authored vs kernel-emitted is a hard boundary (Art I, Art II): the emitters ARE the linter
half of "a standard needs an emitter AND a linter", placed where the model cannot forget them.

## Kernel surface (new): `ui ds pack`

Deterministic, no model calls. Inputs: sealed registry + DESIGN.md + the authored bible +
prompt.md files. Emits: SKILL.md (template), `_pack_manifest.json` (with source hashes for drift
detection), adherence lint config derived from component contracts (prop/variant enums, raw
hex/px/off-system-font bans — reuse `ds-usage-lint` logic where it exists). Refuses to pack an
unsealed/tampered store (depends on 009 Phase 1). `ds status` learns a `pack` freshness check
(pack hash vs registry generation).

## Journey surface (rewritten): the onboard instrument

The code-onboard journey template becomes an **instrument**, not advice. Requirements, all
measured in the PCP artifacts:

1. **Reading-order recipe** — package.json → app layout → token css → shell component → routes
   manifest → representative pages → fixture data; each entry point mapped to the knowledge
   dimension it answers; first exploration reads in ONE parallel batch.
2. **Generated-file heuristic** — a "GENERATED — do not edit" header marks the highest-fidelity
   source: transcribe verbatim, never reinterpret, never round ("5px means 5px").
3. **Usage-count ranking** — count real usage per component across screens; the team-built tier
   outranks library presence (PCP: 0/32 screens used shadcn Card → CardShell is the real card).
4. **Divergence → named props** — differences between consuming apps are intentional; model them
   as props, never normalize.
5. **Reason-with-value provenance** — carry the WHY next to every value; a value without its
   reason gets "corrected" by the next reader.
6. **Coverage checklist** — the answer-ALL question lists for CONTENT / VISUAL / ICONOGRAPHY
   (gradients? hover? press? blur? emoji? casing per slot? unicode-as-icon? …). "None" is an
   answer and is recorded.
7. **Anti-invention guardrails** — source inventory IS the component list; enumerate-before-
   build and track against it; never end silently incomplete (emit "Not built"); no logo in
   source → no logo drawn; mid-run read failure → STOP and report read/unread; explicit
   anti-slop list.

## Gate (Art III)

Run on ≥1 real code repo on this machine (dana or SoDeal preferred). Then the two-session test:
a **fresh** agent session, given only the pack, produces a screen that passes the repo's own
adherence lint and the reviewer's DS-fidelity check. The pack "works" only when a stranger can
use it — consumption is the acceptance test, not emission.

## Non-goals

- Claude-Design-compatible output (`.jsx` quad, `_ds_bundle.js`) — future phase, explicit door.
- Re-implementing user components in any form.
- Slides/UI-kit recreation — PCP needed them as proof inside a walled runtime; our proof is the
  consumption gate against the real repo.
- Healing tampered stores (that is 009 Phase 1's owner-call).
