Release orchestration

Ship on a cadence you set — not the one your pipeline forces on you.

Cadence turns a merged branch into a staged rollout with explicit approval gates: plan the shape of the release, gate it against real checks, ship in the stages you declared, and watch it against the stage before it.

The release model

How a release moves through Cadence

One diagram, followed end to end. Nothing here is a metaphor — these are the four commands `cadence` actually runs, in order, on every deploy.

  1. 01

    Plan

    Declare the rollout shape — canary percentage, target regions, and the rollback condition — before the first byte ships.

  2. 02

    Gate

    Automated checks and a human approval sit between every stage. Nothing advances on a red signal, and nothing advances alone.

  3. 03

    Ship

    Traffic shifts across the stages you declared, not all at once. Cadence drives the rollout; your own infrastructure executes it.

  4. 04

    Observe

    Live error-rate and latency deltas against the previous stage, so a bad release is visible before it becomes a total one.

The actual surface

What it looks like to run

▸ ship      canary 5% › 25% › 100%  (currently 25%, ~12m remaining)
▸ observe   error rate 0.12% (Δ -0.03 vs baseline) · p95 214ms (Δ +6ms)

The network it plugs into

Plugs into what you already run

Cadence orchestrates the rollout. It does not replace your CI, your infrastructure, or your on-call tooling — it drives them in a declared order.

GitHub Actions

Triggers a deploy on merge to the release branch.

GitLab CI

Same trigger model, run as a pipeline stage.

Kubernetes

Default rollout target — canaries via traffic-split.

Terraform

Reads target infrastructure state before a plan is approved.

Datadog

Feeds the observe stage's error-rate and latency deltas.

Prometheus

An alternative metrics source for the observe stage.

PagerDuty

Pages on a gate failure or an aborted rollout.

Slack

Posts every gate decision and stage transition to a channel.

What it assumes

Three things Cadence refuses to compromise on

01

A rollout is not a boolean.

Shipping isn't up or down. It's a sequence of stages you can stop between — and Cadence never collapses that sequence into one deploy button.

02

The gate is a person, by default.

Automated checks can block a stage. Only a human can approve one moving forward, unless a team explicitly configures otherwise.

03

Observability isn't optional plumbing.

A stage with no comparison metric isn't a canary — it's a coin flip. Every stage in Cadence ships with one by construction.
