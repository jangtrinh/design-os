# Data Model: Native Diagram Craft

## Diagram Artifact

- `grammar`: `product-flow | architecture | sequence`
- `readingOrder`: short human-readable traversal declaration
- `focalElement`: stable SVG element identifier
- `sourceKind`: `flow-json | brief`
- `sourceRef`: optional project-relative source path
- HTML document containing exactly the owned inline SVG diagram surface

## SVG Contract

- Root SVG carries `role="img"` and resolving `aria-labelledby` references.
- First owned children include non-empty `<title>` and `<desc>` with artifact-unique IDs.
- Diagram nodes and connectors have unique stable IDs.
- Product-flow nodes/connectors carry source identifiers.
- Connector paths are independently traceable; exact duplicate paths or attach points are invalid when statically provable.

## Fidelity Ledger

- `sourceRef`: flow source path
- `sourceHash`: optional integrity hint, never semantic authority
- `actions[]`: `{ kind: merge | collapse | drop, sourceIds: string[], outputId?: string, reason: string }`
- `complete`: true only when no source semantics are unrepresented

The ledger is generated by the host workflow. The v1 binary validates only embedded/project-provided references it can resolve without inventing semantics.

## Diagram Finding

- `checkId`: stable kebab-case identifier
- `severity`: `error | warning`
- `message`: exact failure plus next action
- `line?`: source line when safely available
- `elementId?`: offending SVG/metadata identifier

Findings sort by severity, check ID, line, then message.

## State Transitions

```text
request -> grammar-selected -> authored -> diagram-linted -> generic-gates -> critiqued -> accepted
product-flow: source-invalid -> blocked (no artifact)
any gate error: authored -> revision -> re-gated
```
